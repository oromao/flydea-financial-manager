## Problema/Oportunidade

**Gap:** P-01

O filtro de Contas a Pagar não funciona de verdade. Os botões de filtro (Atrasadas, Vencem em breve, Todas) alteram o estado `filter`, mas as seções sempre renderizam todos os itens. A lógica atual apenas controla o texto de placeholder, não os dados exibidos.

**Impacto:** Usuário clica em "Atrasadas" e vê todas as seções com placeholders vazios — experiência confusa e frustrante.

---

## Objetivo

Implementar filtro real que mostre apenas as transações relevantes baseado no filtro selecionado.

---

## Descrição

1. **Local:** `src/app/contas-a-pagar/page.tsx`
2. **Problema atual:**
   ```typescript
   // Código atual (incorreto)
   {filter !== "all" && filter !== "overdue" && (
     // Só mostra placeholder, não filtra dados!
   )}
   ```
3. **Solução:**
   - Modificar a lógica para filtrar dados baseado no estado `filter`
   - Opção A (frontend): Filtrar array localmente
   - Opção B (backend): Nova query com filtro server-side
   - **Recomendado:** Opção A (frontend) por simplicidade

## Observações de Implementação

```typescript
// Exemplo de lógica correta
const filteredData = {
  overdue: filter === "all" || filter === "overdue" 
    ? transactions.filter(t => t.type === "EXPENSE" && t.paymentStatus === "PENDING" && t.dueDate < today)
    : [],
  upcoming: filter === "all" || filter === "upcoming"
    ? transactions.filter(t => t.type === "EXPENSE" && t.paymentStatus === "PENDING" && t.dueDate >= today && t.dueDate <= todayPlus7)
    : [],
  noDate: filter === "all" || filter === "noDate"
    ? transactions.filter(t => t.type === "EXPENSE" && t.paymentStatus === "PENDING" && !t.dueDate)
    : [],
};
```
