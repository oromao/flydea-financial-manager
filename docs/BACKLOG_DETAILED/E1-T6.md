# E1-T6 — Adicionar Role Check em Aprovações

## Identificação

- **ID:** E1-T6
- **Tipo:** Segurança 🔴
- **Módulo:** Admin / Aprovações
- **Título:** Adicionar role check em Aprovações (A-05)
- **Prioridade:** P0 (Crítico)
- **Complexidade:** Baixa

---

## Problema/Oportunidade

**Gap:** A-05

A página de Aprovações (`/admin/aprovacoes`) **não tem verificação de role**, diferente de `/admin/logs` que verifica `session?.user?.role !== "ADMIN"`. Qualquer usuário autenticado pode acessar e agir em aprovações.

**Impacto:** Segurança comprometida — usuários comuns podem aprovar/rejeitar ações críticas.

---

## Objetivo

Adicionar guard de admin role em `/admin/aprovacoes` seguindo o mesmo padrão de `/admin/logs`.

---

## Descrição

1. **Referência:** Ver implementação em `src/app/admin/logs/page.tsx`
2. **Adicionar verificação:**
   ```typescript
   const session = await getServerSession(authOptions);
   if (session?.user?.role !== "ADMIN") {
     redirect("/");
   }
   ```
3. **Ou via middleware** se preferível centralizar

---

## Valor para o Negócio

Segurança: apenas admins podem ver e agir em aprovações — proteção de ações críticas.

---

## Impacto no Usuário

- Usuários não-admin são redirecionados
- Acesso restrito a admins
